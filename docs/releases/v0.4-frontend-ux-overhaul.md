# v0.4 Frontend UX Overhaul

Date: 2026-07-09
Branch: `feature/frontend-ux-overhaul`

## Goal

Turn Career Wiki Agent from a collection of functional test pages into a coherent local-first Career OS for daily use.

This release focuses on frontend information architecture, navigation, layout consistency, readable status, and guided workflow UX. It does not add recruiting-platform automation or change backend approval/evidence/export constraints.

## New Information Architecture

Primary navigation is grouped by user workflow:

- Overview: Dashboard, Workflow
- Intake: JD Import, JD Analyzer, Wiki Import, Baseline Resume
- Fit & Evidence: Project Fit, Evidence Editor, Evidence Review
- Resume: Resume Tailor, Resume Versions, Resume Tests, Learning Tasks
- Knowledge: Profile, Project Bank, Skill Matrix
- Operations: Audit Log, Health

## Core Flow

The frontend now presents the main user path as:

JD Import -> Project Fit -> Evidence Review -> Resume Tailor -> Approval -> Resume Versions / Export

Dashboard and Workflow now explain the next action, current blockers, and relevant repair pages.

## Optimized Pages

- Dashboard is now the main home page with hero, workflow cards, metrics, risk panel, and quick actions.
- Workflow is now a readable state board with workflow list, stepper, checklist, timeline, and reason-required transition UI.
- Evidence Review is now a queue with severity summaries, review note requirement, and report export action.
- Audit is now a filterable list/detail viewer with sanitized summaries instead of raw JSON.
- All dynamic Career Wiki pages now share the same App Shell and navigation.
- Resume Tailor / Resume Versions labels were polished to reduce debug-style wording.

## Known Limits

- Evidence Review UI requires a review note before action, but the current backend action contract stores only status. Persisted review notes should be a future backend/API extension.
- Some deep forms inside the existing `ResumeTailorHarness` remain in the large legacy component and should be split into smaller page-specific components later.
- Server-side PDF remains an HTML print fallback by design.

## Next Stage

Recommended next stage: split the legacy Career Wiki harness into smaller feature components and add focused browser screenshot regression checks for desktop and mobile.
